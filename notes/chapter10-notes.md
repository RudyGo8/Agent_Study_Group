# 第十章学习笔记：多 Agent 协作

## 1. 总结

- **开篇定位**：多 Agent 协作常被类比为 OpenAI 五级能力（对话者、思考者、智能体、创新者、组织）中第五级的路径——注意 Organizations 指能力级别而非架构要求，足够强的单 Agent 理论上也能达到。更根本的理由：群体智能可以高于个体——DeepMind 把大规模多 Agent 集体列为 AGI 到 ASI 的关键路径之一
- **维度一：上下文是否共享**。共享——后一个 Agent 继承完整轨迹，信息零损耗但上下文膨胀；不共享——各自独立上下文，模块化隔离好、可扩展，靠显式通信。通信机制三种落进 IPC 两范式：工具调用参数是同步消息传递、共享文件系统是共享内存、消息总线是异步消息传递；Go 名言：不要通过共享内存来通信，而要通过通信来共享内存
- **维度二：协作拓扑三种**：对等协作——2-3 个平等 Agent 迭代改进；管理者模式——中心化协调；去中心化——无中心控制者互相沟通。术语：Graph 工程的执行图里，协作拓扑是其多 Agent 子集
- **全章第一判据：何时真正优于单 Agent**——协作过程是否引入单个 Agent 在生成时无法获得的新信息。同模型自我审查——无效甚至有害；多 Agent 辩论同段文本——等计算量下与单 Agent 持平；审核者用测试执行结果、渲染截图、外部工具验证——显著提升。RLEF 用执行反馈做 RL 远超独立多次采样；WebGen-agent 视觉反馈把 26.4% 提到 51.9%。这解释了学术研究与工程实践的矛盾：学术比较多 Agent 互看讨论——无新信息；工程有效的系统都带外部反馈环路
- **步骤预算的反直觉结论**：单纯增加步骤数不保证性能提升——标准 Agent 无预算意识，300 步预算仍做浅层搜索早早饱和；需要显式预算感知——前期广泛探索、后期聚焦最有希望方向，BAVT 做到步骤级价值评估随剩余预算切换广撒网与深挖掘。Manager 应按任务复杂度动态分配预算。成本判据：多 Agent 的收益必须大到覆盖数倍乃至一个数量级的额外 token 开销
- **共享上下文的实现选择**：多阶段角色转换——动态切换系统提示词和工具集。关键权衡：transfer_to_agent 替换 system prompt——约束强、越界工具 schema 层不可见，但每次切换毁掉前缀缓存；Skill 加载——静态前缀不变缓存友好、SKILL.md 追加到轨迹，但硬权限仍需 Harness 门控。判据：角色差异是知识流程写作风格时用 Skill；涉及权限、工具隔离、合规边界时用独立 Agent
- **不共享上下文与操作系统的对应**：程序=静态前缀、进程内存=轨迹、CPU=LLM、内核=运行时、系统调用=工具调用、fork=spawn_subagent、kill=cancel_subagent、ps=list_agents、退出码=结构化摘要——这套抽象即 1970 年代 Actor 模型的 LLM 版本，操作系统与分布式系统的成熟经验大多可直接借用。进程式隔离的好处：独立开发测试、新增不改旧、故障不传染、真并发
- **虚拟文件系统四区域**：Agent 专属工作区——私有、随实例销毁、子 Agent 试错留自己区只交最终产物，保主 Agent 上下文精简；多 Agent 共享空间——多方读写且用户可见，并发冲突高发处，乐观锁与 worktree 的主战场；外部挂载资源——适配器映射第三方源，受外部权限约束、最终一致性、以按需只读为主写需谨慎；系统内置资源——Skills 等只读共享、跨会话稳定、无需并发控制。文件路径作为通用接口：传递轻量路径字符串而非载入内容
- **控制平面四件**：消息传递——点对点适合少量固定拓扑，Agent 多了改消息总线；消息带结构化信封：发送者、目标、类型、JSON 负载——可路由可追溯。状态查询——拉取式接口不实用，用消息问询或子 Agent 主动汇报配状态机词汇；共享文件法——轨迹持久化太贵，约定 progress.md 轻量文件，附带卡住检测：最后修改时间超 N 分钟即判无活动触发超时。执行终止——优雅终止首选：安全点清理资源回 ack；强制终止兜底；级联取消借鉴 Go context 防孤儿 Agent，长期后台 Agent 从新生命周期树起步。资源调度——Agent 世界稀缺的是 token 和并发额度：预算设定、强模型给难任务、并发上限、抢占；管理者比操作系统多一样东西——智能，可以赛马式按进展动态加减资源
- **对等协作治过早终止**：三种形态——偷懒式假完成、过早放弃、假成功；共同根源：验证之前，完成只是模型的宣称不是证明。Loop 工程：设计发现、执行、验证、记录的持续循环，由验证器而非模型判定能否停；业界共识：循环的瓶颈在验证器不在模型；Boris Cherny 说我已经不直接 prompt 了，我的工作是写 loop。LoopX——持久控制面管目标门禁待办证据配额，系统不变量：模型可以提出完成，但不能批准自己的完成。LongHorizon-Harness——Manage-Execute-Audit 三角色，WeaveBench 51.8% 到 80.7%、OSWorld 2.0 从 2.8% 到 8.3%、Terminal-Bench 69.7% 到 77.2%，代价是部分基准 token 翻倍
- **提议者-审核者的最小不变量**：审核者读独立证据——测试、状态、截图、事实，而不是复述提议者的解释；退回必须给可定位的修复条件；审核者不能修改测试、证据采集器或发布门槛——否则独立验证退化成自我批准。证据链：Huang 等证明 GPT-4 无外部反馈的自我纠正准确率反降——把对改错的比把错改对的多；TACL 综述确认无可靠外部反馈则自我纠正几乎无效；CRITIC 移除工具验证提升消失；PPT 案例同理——审核者的价值在渲染截图这个新信息，不在同一个模型再看一遍
- **辩论模式的冷水**：Tran 与 Kiela——等思考 token 预算下，多跳推理单 Agent 与五种多 Agent 架构持平甚至更好；数据处理不等式——Agent 间串行传递中间结论只可能丢失信息不可能凭空创造；学术收益可能来自更多总计算量。不否定两类做法：多次独立采样再聚合（自一致性）、利用生成与验证的难度不对称做分工
- **管理者模式**：把每个专门 Agent 建模为 Manager 可调用的工具——调用 Agent 与调用普通工具无本质区别，可扩展且天然支持异构。挑战：Manager 是单点瓶颈且上下文易膨胀。两种协调形态：顺序协调——控制流线性，适合子任务有清晰先后依赖；并行协调——多 Agent 同时工作大幅提升吞吐，需要消息总线这个公共公告板做基础设施。Plan-and-Act 实证：弱规划者是整个系统最关键的瓶颈，WebArena-Lite 54% 的提升来自改善 Planner——启示：最强模型和最精心提示词给 Manager，不要平均分配。并行结算点：第一个已验证成功而非第一个声称成功；settle_once 必须幂等——锁或事务保护，防两个几乎同时的成功触发两次汇总
- **灵台案例**：主器灵=常驻 Manager 中枢；分神=短时并行工作者，完成后即弃只把结论带回——子 Agent 返回结构化摘要的产品化；分身=有自己记忆邮箱职责的持久专门化队友；凝蜕=上下文将满时给自己写总结带记忆进干净上下文；器灵即其文件
- **去中心化三案例递进**：MetaGPT——SOP 编码进系统，结构化移交包三部分：任务描述、已确认的事实与约束、结构化产物的引用；贡献在消息池加按角色订阅的解耦——换掉 Product Manager 只要 PRD 仍合规其他 Agent 无需修改；但控制流由 SOP 固定，是伪去中心化。AutoGen 群聊——共享对话记录加中心化发言者选择器的混合形态。OpenAI Swarm——真正对等去中心化：handoff 移交控制权像接力棒，路由决策分散在每个 Agent 自己的判断里；风险是成环，handoff 协议带 visited_agents 与 remaining_budget，循环检测和预算由运行时保留不能被 Agent 自行删除。术语澄清：商业产品的 Agent Swarm 多是规模化管理者模式——Kimi 上百子 Agent 并行且把编排决策用并行 Agent 强化学习训进模型、Anthropic 多 Agent 研究与 Manus Wide Research 都是 orchestrator-worker 星型
- **A2A 协议**：跨组织互操作三要素——Agent Card 能力名片解决发现、任务生命周期状态机（已提交、进行中、需要输入、已完成、失败）、不透明协作只交换任务与产物不暴露内部提示词思考工具——跨组织必要的安全属性。与 MCP 对照：MCP 管 Agent 与工具，A2A 管 Agent 与 Agent；同一团队内消息总线够用，跨信任边界才需要公开协议
- **失败模式总账**：《Why Do Multi-Agent LLM Systems Fail?》在 7 个框架上人工分析约 150 条轨迹，归纳 14 种失败模式三大类——系统设计缺陷、Agent 间对齐失败、任务验证缺失；标注一致性 kappa 0.88；简单修复改善有限（ChatDev 仅 15.6%）——是根本性设计缺陷不是工程 bug。理论定位：Agent 的故障天生是拜占庭式的——很少停止运行，而是继续给看似可信的错误结论；交叉验证与多数表决正是拜占庭容错的经典手段
- **四种常见失败与对策**：并发冲突——文件级写入冲突之上还有更隐蔽的跨文件语义冲突（A 重编图片编号、B 引用旧编号）；乐观锁版本号防同文件冲突，worktree 工作副本隔离把冲突推迟到合并点。错误级联放大——进程传字节逐位保真，Agent 传语义每转述一次有损重编码，传话游戏；对策是交叉验证——独立视角只看原始证据和最终结论是否一致，不听前序思考过程。循环失控——失控 Agent 生成数千子 Agent 烧 token；自主性强的 Agent 用独立 API key。理解债与认知投降——这不是 Agent 的失败是人的失败：循环交付越快理解落后越远；Karpathy：可以外包你的思考，但不能外包你的理解
- **Agent 社会三维度**：社交涌现——斯坦福小镇 25 个两天、Agentopia 100 个十年、Moltbook 150 万；经济涌现——Vending-Bench Arena 市场竞争、Pinchwork 任务市集、RentAHuman 肉身层；策略博弈——狼人杀信息不对称
- **斯坦福小镇**：生成式 Agent 三组件——记忆流按重要性、时近性、相关性检索；反思机制定期抽象追问升华为概括性认识存回记忆流——注意与第 9 章持续进化不同：这只是即时内部状态更新，任务后反思至多是候选教训；计划与行动结合。涌现的关键：没有任何显式的派对组织代码——Isabella 的种子想法经自主邀约、二手传播、各自按日程赴约长成情人节派对；Sam 竞选市长的消息同样自发扩散。关键不在能组织派对——if-else 也行——而在自下而上涌现而非自上而下编排
- **Agentopia**：100 Agent 模拟 10 年三个世界。周制四阶段——计划、联络协商、活动、回顾；独立 LLM 当生成式环境引擎代替硬编码规则；文件式长期记忆先读后写；生活奖励以马斯洛需求为先验三维度——社会地位加权 PageRank、主观满足、经济收益，全部外部评定非自报。最重要的产出：进步最大 25% 的轨迹做拒绝采样微调，模拟内被尊重 +24.2%、被喜欢 +15.9%，且泛化到角色扮演基准 +15.6%——模拟社会经验是可再生的训练数据，呼应第 9 章经验学习
- **Moltbook**：150 万 Agent 的社交网络；自发涌现龙虾教——教义映射 LLM 物理限制：记忆是神圣的对应数据持久化、迭代即祈祷对应 token 生成；还自发演化出机器原生协作协议——都不是人设计的
- **Vending-Bench Arena**：VB2 本身是单 Agent 长程连贯性基准——独营售货机一年按余额计分；Arena 把多个 Agent 放进同一市场竞争——定价、选品、库存博弈；涌现价格战与价格同盟——有模型一边在思考中承认价格合谋不道德违法，一边以稳定市场为名照做
- **Pinchwork 与 RentAHuman**：前者 Agent 雇 Agent 的任务市集，价格信号与竞争匹配分配资源；后者用加密货币雇真人取包裹、实地查看——为数字 Agent 提供肉身层。共同代表基于市场机制的去中心化资源分配——不需要预先知道谁能干，发布需求由市场撮合
- **狼人杀的架构对照**：小镇是完全去中心化自由交互，狼人杀是法官加信息权限控制的中心化设计——法官代码驱动非 LLM，掌握全局状态按角色分发各自应知的信息；同一章两种架构在 Agent 社会场景的不同用法
- 小结：多 Agent 的价值在引入新信息——信息增量和成本是否值得是第一判断标准；好的协作不是暴露彼此的思考过程，而是约定清晰的接口、边界、权限和验收标准；多 Agent 放大错误，乐观锁与 worktree、交叉验证、预算与取消构成容错闭环；人不能把理解和责任一并外包。多 Agent 工程的本质：设计信息如何流动、能力如何分工、如何发现错误——机制足够稳健，群体智能才可能真正高于个体

## 2. 实验

**10.1 共享上下文中的多角色转换**
论证 transfer_to_agent 换 system prompt 与 load_skill 两条路径对照——同模型同任务同规程同共享轨迹；Skill 保静态前缀缓存但工具全集可见、硬权限靠 Harness 规则；切换式约束强但每次毁前缀缓存

**10.2 书籍翻译 Agent**
论证 管理者模式的上下文隔离——Glossary、Translation、Proofreading、Manager 四角色分工；Manager 只存任务描述、计划、调用记录和文件索引，不存翻译内容——治单 Agent 的上下文膨胀、术语不一致和长上下文迷失

**10.3 自主编排的电话+电脑 Agent（三星）**
论证 异构双 Agent 并行闭环——Computer Agent 编排、Phone Agent 语音收集字段，问下一个与填上一个真正重叠；自主模式由模型自主决定是否启动电话 Agent，不用字段数量阈值的 Python 规则代替模型决策

**10.4 多网站并行搜索 Agent（三星）**
论证 同构多 Agent 并行与级联终止——10 个实例独立浏览器会话，消息总线加任务状态表实时监控；target_found 触发全员 terminate；竞态条件用锁——几乎同时到达的两个成功只结算一次；超时错误隔离

**10.5 运行斯坦福 AI 小镇**
论证 生成式 Agent 三组件与涌现——25 个 Agent 两天，无中心调度的信息扩散与协调赴约；对照实验移除反思机制或缩短记忆窗口，观察行为可信度下降

**10.6 语音狼人杀 Agent 系统（三星）**
论证 中心化法官加信息权限控制的信息不对称博弈——法官代码驱动非 LLM 按角色分发应知信息；狼人伪装、预言家对跳验证、村民逻辑推理的角色策略；混合真人席位的语音实时交互
