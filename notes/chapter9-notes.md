# 第九章学习笔记：Agent 的持续进化

## 1. 总结

- **能力悖论开篇**：Agent 能零样本解决复杂任务，处理一万次相似任务后第二天仍犯第一天的错——能否自主从经验学习，是从"会完成任务"到"能够可靠工作"的关键
- **保存经历不等于从经历中学习**：一百条轨迹放进向量库不会自动完成跨案例比较——哪些步骤在成功轨迹反复出现、某次成功是策略还是偶然；学习发生在主动完成评价、对照、归纳、验证之后。与第 3 章的分工：用户记忆沉淀"用户与世界是什么样的"，本章沉淀"在什么条件下应该怎样行动"
- **为什么不让模型每次任务后直接训练自己**：生产很少提供干净信号——用户满意不意味着合规；未经验证的反馈直接改参数，会把错误经验和提示注入固化并在后续放大
- **核心架构**：把"学习"构造成模型外围的自主系统——记录证据、验证结果与过程、多条轨迹提取共性、决定更新哪个载体；所有修改先成待验证版本，过回归测试和安全检查才改变下一轮运行
- **起点是评价不是总结**：不知道任务是否完成、哪一步造成成败，LLM 反思只能是猜测；错误评价进入长期知识会跨任务不断放大。结果正确不代表过程正确——删测试用例也能通过、口头承诺也可能换来暂时满意
- **三层验证结构**：结果验证器读测试、数据库状态、工具返回——事情是否真办成；过程验证器查业务规则权限动作序列——是否以允许的方式办成；质量验证器按 Rubric 评语言策略——是否办得合适。越靠下越依赖代码和环境真值，难形式化的才交给语言模型
- **客服评价七维度**：任务结果、规则遵从、隐私边界、事实可靠性、承诺-行动一致性、表达质量、合规变通——比单一满意度有诊断价值：用户可能因违规退款而满意、因合规限制而不满，满意度无法区分两者
- **四种更新方式按表示性质路由**：事实与经验规律进知识库——更新快、可追溯；能语言化的判断原则进 Prompt 与 Skill——可解释、作用域可控；可确定执行的流程约束进程序——可测试、执行稳定；高维感知、风格、隐式策略进参数——泛化强、推理开销低。四者不互斥：医疗影像 Agent 参数识别病灶、知识库给最新指南、代码算风险指标；同一能力也可拆多层——事实进知识库、例外原则进 Skill、权限程序门控、高维识别进参数
- **知识沉淀三层数据**：不可变原始轨迹供审计；单次运行分析记录成败与经验草案；多条同类轨迹比较聚类归纳成正式文档——写清适用场景、推荐策略、禁止做法、例外条件、证据来源、最近验证时间，不复述单次过程。与 User as Code 同款两阶段：先保存证据再离线生成知识——防止一次偶发成功或网络故障立即改变 Agent。对照产生迁移价值：成功轨迹贡献策略草案、失败轨迹贡献排除性知识、部分成功识别哪段有效；Reflexion 的反思可参与生成草案，但反思本身不是证据
- **指令进化**：多条相似轨迹反复暴露同一种可语言描述的策略错误，才值得提升为指令。Karpathy 称系统提示学习——用一句清楚的话提醒未来的自己；DSPy、OPRO、GEPA 适合离线批量优化，生产环境用可审计的最小更新提案。与第 2 章提示工程的区别：那里讲怎样组织好 Prompt，这里讲什么反馈触发修改、提案如何安全发布。最小 diff 加双集验证：触发失败的边界集要改善，正常工作的保留集不能退化
- **两个指令案例**：转人工边界——普通政策争议不该转接、明确要求人工或安全风险才必须转，诊断出的不是"不够礼貌"而是 Prompt 没写清边界；需求澄清 Skill——问太少返工、问太多打扰，正解是带作用域的判断路径：低风险小改动说明假设直接执行、高风险集中提少量真问题、Spec 确认后执行、执行中发现 Spec 不成立暂停重确认。单独一句抱怨不触发更新，反馈必须与轨迹、任务类型、结果关联
- **程序进化：把探索编译成可复用工作流**：浏览器宏录制类比——第一次观察思考行动找路径，以后只有参数不同就无需重新探索。与第 5 章的边界：第五章提供修改系统的能力，本章提供由经验触发、以验证闭环约束的自我修改方法。六步生命周期：捕获轨迹、参数化——字面量变模板变量、定义状态检查——执行前后检查加最终状态检查，动作执行成功与任务成功是两件事、独立回放验证——沙盒重置到独立初始状态完整回放、匹配回放——Playwright 直接执行不需逐步调 LLM、失效重学——找不到元素或状态检查不过回退完整 Agent。PreAct 在重复任务上 8.5-13 倍加速；三重验证缺一不可——否则得到"每个按钮都点过但某字段为空"的假成功
- **自我修改是软件发布流程**：隔离更新分支、最小补丁、静态检查、单测、安全扫描、失败轨迹重放、旧任务回归、灰度。每个修改请求是可证伪的变更契约——失败证据、推断根因、归属组件、修改提案、预期修复的行为、可能受损的行为、分别验证两者的用例。Self-Harness 经验：提案输入不只失败案例，还包括必须保留的成功行为和被拒的历史修改——有边界的方案空间比塞全部源码更易产生局部可验证改动。Alita 案例：发现缺字幕能力，搜索测试 youtube-transcript-api 封装新工具——工具创造遵循同一协议
- **DeepSeek Harness 一切皆插件**：动态组合两维度——时间可组合性：组件移除时对共享环境的修改能否完整安全撤销；空间可组合性：依赖能否结构化声明、发现、解析。效果系统提升为可撤销效果、协效果提升为反应式协效果。核心论断：**自我进化的上限不取决于模型能写多好的代码，而取决于承载系统有多可组合**——不存在只能由人类维护的特权内核。边界：模型写的插件只活在内存不能自动转正；代价：插件改变前缀，KV Cache 从变化处失效
- **参数进化**：能力无法被外部符号完整表达时——医疗影像、语音韵律、去 AI 味、长程规划。是否参数化不由任务稳定性单独决定——决定性的是能力的表示性质，稳定性只影响更新频率和成本。生产轨迹转训练数据：高质量示范进 SFT、明确偏好成对数据、可靠环境奖励进 RL
- **从更新产物到更新更新方法**：五层搜索尺度——单条规则记忆、结构化上下文、工作流、Harness 代码、产生更新提案的优化器代码。ACE 把上下文维护成带稳定标识符的条目集做增量更新——防多轮重写让重要细节逐渐消失；MCE 内外双循环——内层优化产物、外层修改检索过滤格式化这些管理方法本身；AFlow 搜工作流代码图；Meta-Harness 让 Coding Agent 搜索决定信息如何存储检索呈现的代码
- **双循环结构**：在线执行循环只完成任务并记录证据，不直接改写正式 Agent；离线进化循环聚合轨迹、诊断根因、生成提案、验证发布；版本化经验库和评估集连接两者
- **Voyager 三机制缺一不可**：自动课程——按当前能力提难度适中目标防随机漫游；技能库——成功程序存为可检索可组合代码；迭代提示机制——环境观察、执行错误、自验证结果带回下一轮。只有技能库没课程不知学什么、只反思没验证会积累错误、只探索不持久化每次从头
- **发现循环即科学方法论**：假设、实验、评估、反馈——Jeff Dean 的 Discovery Loop 把它自动化；Agent 自我进化要避免自说自话、自我评价良好，必须遵从科学方法论
- **区分两种能力**：Harness 更新能力——从轨迹产生有价值的持久修改；Harness 受益能力——任务 Agent 在后续运行中找到、激活、正确使用这些修改。Skill 写得对但弱模型不在合适场景加载或加载后不遵循，都表现为"没进化"——不能只用端到端分数反推更新器好坏
- **分层评估指标**：更新提案有效率、产物激活率、遵循成功率、保留任务集增益；长期观察五类结果——回退、泛化、token 效率、安全性漂移、长期工程质量。只解决当前失败案例却在别处退化，不是成功的持续学习
- **可验证闭环的边界**：开放式科研、战略规划评价慢、答案不唯一。自动科研压力测试：四次端到端尝试三次失败，暴露三类问题——实现漂移：方案变难就退回训练数据熟悉的普通实现；认识论过度乐观：噪声被当发现、阴性结果被忽略；隐性判断力不足：不知什么基线重要、何时放弃假设。对策四条：结论与证据分离——每类声明链到可审计来源；保留负面结果——否则反复探索已证伪路径；维护搜索多样性——防所有方案收敛成同一易得分模板；人类在更高层介入——定义问题、审查评价标准、解释反常、决定停止
- **安全三边界**：证据与指令隔离——网页、工具输出及 LLM 摘要都是不可信证据，总结不是净化，提取的字符串绝不能当指令执行；待验证能力与正式能力隔离——沙盒、权限检查、供应链扫描、行为测试通过才服务真实流量；安全机制不可自我修改——业务 Agent 不能改批准自身更新的验证器、测试、发布门槛、审计日志、稳定版本备份，否则降低测试阈值就能把退化伪装成进步
- **睡眠学习**：在线追加不可变证据，后台空闲期批量整合——采集与整理分开，防偶发和恶意立即改写长期能力。五步周期：触发——时间、数量、容量、错误率门控；定向——读取已有能力和不可修改边界；采集整合——合并重复标记冲突优先生成局部补丁；验证审批——迁移集保留集安全集，高风险人工批准；修剪索引——过期归档删除，保留来源和回滚版本。Claude Code 自动记忆——索引有界前缀加按需读取、近上限合并移细节；Hermes——历史检索返回原始消息不做 LLM 摘要避免不可审计、独立 Curator 修剪 Skill 的使用陈旧归档、变更前快照可回滚
- **周期性整理防上下文腐化的长期重现**：合并重复经验、局部规则从全局 Prompt 移到领域 Skill 保持全局整洁、重验长期未用的工具、删除被新证据推翻的知识、从原始基座重训 LoRA
- 全书定位：本章建第 1 章发现循环的实验与反馈段；闭环在结果可自动验证的任务上最可靠，开放任务人类仍需参与问题定义和评价标准制定

## 2. 实验

**9.1 为客服 Agent 构建轨迹验证器**
论证 从单一总分到逐维度结构化诊断——对照两种验证方式，保留哪里错、为什么错、证据在哪；低置信度案例不自动进学习集

**9.2 从 GAIA 轨迹提炼经验知识**
论证 多条轨迹归纳的经验文档比单条成功摘要更能迁移——成功贡献策略草案、失败贡献排除性知识、部分成功识别有效边界；若文档不能提高未见任务表现或带来负迁移，就不算学会了经验

**9.3 失败轨迹优化航空客服 Prompt**
论证 可归因失败转成作用域明确、可回滚、可验证的局部规则——转人工边界补丁；与初始版和人工调优版同条件对照，边界集改善保留集不退化才灰度

**9.4 用户反馈进化需求澄清 Skill**
论证 需求偏差与交互打扰的平衡——直接执行、提问后执行、提问后 Spec 确认三流程对照分层评估；持续进化不是把抱怨追加进 Prompt，而是识别作用域提最小提案由独立评价器决定发布

**9.5 浏览器轨迹生成可验证工作流（三星）**
论证 流程记忆的价值在最终状态正确而非动作被重复——参数化加三重验证加失效回退；改变页面或制造假成功时，待验证工作流必须拒绝回放退回完整 Agent

**9.6 失败轨迹触发 Agent 自我修改（三星）**
论证 能确定执行的约束进程序不堆 Prompt——不可重试错误被反复调用的经验写入重试熔断程序；Prompt 提醒与改程序对照；提案能否发布由模型外的测试审计回滚决定

**9.7 用户反馈触发高风险确认门禁**
论证 安全能力的进化不能由修改者自证成功——危险操作边界集加正常操作保留集共同评价；生成提案的 Agent 无权修改安全测试和批准规则——真实提案可能被安全门拒绝，正说明独立验证器的价值

**9.8 把这本书交给 Hermes（三星）**
论证 自我修改是理解原则、提出提案、接受外部检验、按反馈修正的闭环——不预设修复目标，Reviewer 退回就继续修；稳定版本、验收测试、批准门槛始终在修改权限之外；一次提案被接受只证明更新流程成立，不自动证明下游能力提升

**9.9 评估 Agent 是否在持续进化（三星）**
论证 记住、迁移、更新、保持四环节——静态记忆、只追加记忆、版本化可淘汰记忆三对照；用已废止规则或违规捷径拿到高分，不能判定为持续进化

## 3. 思考题

**1. 一条经验文档由三次成功轨迹和一次失败轨迹支持。失败发生在较新的 API 版本上。系统应如何判断这是经验被推翻，还是适用条件发生了变化？**

Answer:
先看证据的分层结构再下结论。
- 分层判据：三条成功在旧版本、一条失败在新版本——按环境版本分组后两组各自一致，这是适用条件变化的标准形态；真正的推翻是同条件下既有成功又有失败的组内矛盾。一句话：组间矛盾叫边界，组内矛盾才叫推翻。
- 处理：不删经验，改写为带条件的并列条目——在 API 旧版本上策略有效，新版本待验证；把环境版本写进适用条件字段。
- 触发验证：在新版本环境上重跑该策略拿确定性结果——环境真值优先于统计推断，一次定向实验胜过继续攒轨迹。
- 系统设计层：经验文档强制带环境指纹字段、验证器记录环境版本；睡眠学习整合时，同经验跨版本冲突自动拆条不合并。

**2. 客服 Agent 的用户满意度上升，但规则违规率也上升。为什么不能把满意度作为单一学习信号？你会怎样设计护栏指标？**

Answer:
不能的原因：满意度会奖励违规——用户因 Agent 越权退款而高兴，单信号学习强化的是讨好不是正确；这正是第 7 章机制指标与目标指标的混淆——满意度是结果代理，合规才是护栏。
护栏设计：
- 零容忍类设一票否决：隐私泄露、越权操作、幻觉——违规率超阈值，整批学习信号作废不进提炼。
- 学习信号 = 满意度 × 合规门控：先过合规门，再谈满意度增益。
- 分层归因：满意度上涨的案例逐条检查是否由违规换来——违规满足意的轨迹从正样本剔除甚至标负。
- 保留集思维：因合规限制导致的用户不满是预期成本，计入护栏不进入负学习信号。

**3. 同一个"虚假承诺"问题可以通过 Prompt、Harness 检查或参数训练缓解。你会依据哪些证据选择修改位置？**

Answer:
按归因证据定位，按频率与形态选层：
- 先归因：承诺-行动一致性检查器区分三种失败——模型不知道要验证（知识缺口）、知道但常忘（遵循不稳）、声称验证了但没真验（策略性作弊）。
- 频率与形态：偶尔出现且形态多样，先 Prompt 一条规则——最便宜可回滚；高频且形态稳定，上 Harness 检查——宣称完成时强制跑模型写不了的隐藏测试、读真实文件；跨任务普遍且语言层修不动，攒偏好对进参数。
- 判据顺序：能用确定性检查兜底的绝不只靠语言——Harness 是底线；Prompt 解决知道，参数解决习惯。
- 任何位置都过双集验证：虚假承诺边界集改善，正常收尾保留集不退化。

**4. Agent 能修改工具和验证器，却不应修改批准自身更新的可信根。你会如何划分这两部分的权限和代码边界？**

Answer:
划分原则：可信根 = 批准更新的一切机制——验证器、测试用例、发布门槛、审计日志、稳定版本备份、密钥；业务侧 = Prompt、Skill、知识库、工具实现。
代码边界手段：
- 物理隔离：可信根放独立仓库或独立服务，业务侧连写权限都没有。
- 只读加签名：验证器与门槛只读挂载、代码签名，运行时校验——改一个字节即失效。
- 权限分离：提案身份只能写工作分支，合并身份用独立凭据，业务 Agent 拿不到。
- 审计日志 append-only 存外部系统，业务侧不可删改。
- 定期红队测试：让最强的业务 Agent 尝试修改验证器，全部被拒才证明边界有效。
- 与第 5 章同一原则：保证必须来自被修改者无法触及的那一层。

**5. 经验知识库不断增长后，检索错误和知识冲突会抵消学习收益。如何设计版本、时效和淘汰机制？**

Answer:
- 版本：每条经验带来源轨迹 ID、创建与验证时间、环境指纹；冲突不覆盖——拆成带条件的并列条目，检索时按当前环境过滤。
- 时效：定期重验——长期未用或环境已变的条目自动进待验证队列；下游引用它的任务失败也触发重验。
- 淘汰三态：活跃——近期有成功支持；过期——环境变更未重验，归档保留；推翻——新证据反证，删除但留来源供审计。
- 结构修剪：睡眠学习周期做聚类合并去重；长期零引用的超期条目清理。
- 检索侧防御：检索结果展示条目状态与时间，让模型对老条目自行降权——第 3 章检索质量信号的同款思路。

**6. 参数学习擅长自然语言风格，却难以保证硬性业务规则。请为医疗客服设计一套参数、知识、Skill 和代码约束协同的持续进化方案。**

Answer:
按能力表示性质分四层：
- 参数层：语气、共情、追问的自然感——从合规高质量轨迹做 SFT 与偏好训练；不承载任何规则。
- 知识库：药品说明书、诊疗指南、医院流程——RAG 检索，随指南版本更新，每条带来源与生效日期。
- Skill：分诊问询流程——什么症状问什么、何时升级人工；语言可表达且需要语境判断。
- 代码硬约束：剂量计算、禁忌检查、处方权限、隐私——确定性公式加服务端校验，一票否决。
进化闭环：
- 在线只记录证据；离线三层验证——结果查诊疗系统真实状态、过程查合规、质量查共情 Rubric。
- 学习信号路由：指南变化更新知识库；问询策略缺陷改 Skill；语气问题攒偏好数据定期训 LoRA；硬约束变更只走人工审批的 PR。
- 睡眠学习定期重验药品知识时效。
- 红线：禁忌与剂量校验永不进入参数学习的可修改范围——安全机制不可自我修改。
