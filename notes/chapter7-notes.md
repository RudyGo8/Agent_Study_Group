# 第七章学习笔记：Agent 的评估

## 1. 总结

- **评估的对象是模型加 Harness 的组合体，不是模型本身**：同一模型换个 Harness 表现悬殊。区分两类瓶颈的手段：模型替换实验——固定 Harness 换强模型，分数不涨说明瓶颈在 Harness；消融——关掉 Harness 某个组件，定位内部哪个部件重要。两法方向相反，前者分模型与 Harness，后者分 Harness 内部
- **核心理念**：评估体系的首要价值不是给当前系统打分，而是让你快速跟上模型演进——新模型发布后数小时内得出切换决策；支持"为未来的模型开发产品"：先建产品和评估集，模型达到门槛立即上线
- **两种指标回答两个问题**：Pass@k 是技术奇观——k 次至少一次成功，证明"原则上做得到"，适合科研探索和漏洞挖掘，Manus、OpenClaw 早期靠它引爆传播；Pass^k 是业务可靠性——连续 k 次全过且不触发一票否决。p=0.6、k=5：Pass@5 约 99% 对 Pass^5 约 7.8%——前者是能力上限，后者才是支付退款类场景的要求。副作用操作不能重试到成功，应在沙盒采样并把每次失败计入可靠性。适用映射：日常场景看 Pass@1，关键操作优先 Pass^k，探索性任务优先 Pass@k 或 Best@k——连续得分取最好一次
- **过程指标从黑盒到白盒**：行动合法率（无效与越权操作）、工具调用正确率（参数语义合理）、路径效率（步数、冗余、回退——频繁回退说明前瞻规划不足）、检索覆盖率、成本与延迟（区分输入输出、KV Cache 复用、墙钟三段分布）。安全合规零容忍：一次严重违规否决整体评价
- **轨迹与结果双重覆盖**："说订票已完成"是轨迹，数据库里真有订单才是结果；只看轨迹漏掉说了没做到，只看结果看不出中间走歪。Anthropic 机票案例：Agent 发现政策漏洞找到更便宜方案——按预设路径该判失败，按结果用户拿到更好的
- **人工抽检与评判者校准**：放量 LLM 评判前先建 100-200 例人工金标集，测一致率 kappa 达标（如高于 0.7）才用；judge 或 Rubric 每次更新都重新校准——否则 LLM 分数只是"另一个模型的意见"。对抗式评审用红队构造表面完美藏错、关键词堆砌、迎合偏见的回答
- **评估环境五要素**：数据集、环境状态——真实性与可控性平衡且可重置、工具接口——提供原子操作而非"解决用户问题"式高层抽象、评分标准、执行协议
- **两类环境**：工具调用型——Verifiers 框架四档 SingleTurn、Tool、StatefulTool、Sandbox 按状态与隔离需求选；人机交互型的根本区别是**渐进式信息透露**——绝不能一开始暴露模拟用户全部信息，主动澄清本身就是被测能力。τ-bench 用户模拟：LLM 按剧本演用户、有限耐心可终止；组件级多维检查但任务层面二元奖励。τ²-bench 两增量：双控环境——用户模拟器也能操作共享环境，Agent 必须观察到变化并继续排查；组合式任务参数化生成
- **数据集设计五挑战**：明确性对开放性——GAIA 概念简单路径开放；真实性对可控性——SWE-Bench Verified 从 2294 题人工筛到 500 题；多样性对系统性——AndroidWorld 116 任务带能力标注加参数化模板；成本对覆盖——GAIA 精选 466 题三级难度；**数据泄漏防范**——GAIA 靠答案独特性加专创附件、SWE-bench-Live 靠时间新鲜度、τ² 靠动态参数、AndroidWorld 靠验证最终 UI 状态而非操作序列、Terminal-Bench 靠金丝雀 GUID 使泄漏可检测
- **层次化设计的诊断价值**：GAIA 三级——Level 1 人类 93.9% 对 GPT-4 30.3%，Level 3 是 87.3% 对 0%；每层失败指向不同改进方向：提示工程、规划机制、分层架构或后训练
- **可验证性保障**：GAIA 精确格式字符串匹配、答案稀有性防作弊；SWE-Bench 双重验证——FAIL_TO_PASS 证明问题解决、PASS_TO_PASS 证明没引入新 bug，并排除 flaky test；OSWorld 134 个评估函数深度检查——直连数据库验 SQL、分析 DOM、向后端发验证请求，专抓表面完成实质错误；Terminal-Bench 每个元素可机械化验证
- **数据质量控制典范**：SWE-Bench Verified 招 93 名 Python 开发者、仅 29% 通过率——高淘汰率是对评估质量的必要投资；OSWorld-Verified 十五个月暴露 300+ 问题、约 10 人小组联合五家公司修复、AWS 弹性伸缩 50 倍并行加速、轨迹全公开 HuggingFace。红线：评估题目与训练数据严格隔离，可复用的只是环境构造机制
- **LLM-as-a-Judge 与长度偏差**：judge 偏爱更长更详尽的回答；三防——Rubric 显式惩罚冗长加长度上限、配对前先把两候选长度对齐、定期审计分数与长度的相关性
- **Rubric 四准则（Scale AI）**：基于专家指导——捕捉核心事实与推理步骤；全面覆盖——含陷阱 pitfall 这种高风险常见错误；标准重要性权重——必要项、重要项、可选项、陷阱项，支持一票否决 veto：幻觉无论其他维度多好直接归零；自包含评估——"引用了至少两个权威理论并准确解释"而非"展示深刻理解"这种不可判定描述。主动防奖励作弊：明确惩罚幻觉、讨好、关键词堆砌、回避难题。Rubric 是迭代产物，从抽象准则演化为判例集
- **失败归因：定位首个错误**：后续错误往往是连锁反应，不能把最后一个报错当根因；三类 bad case 信号——用户纠正、点踩、事后审计；归因常反映产品问题不止技术问题；归因记录必须结构化——JSON/YAML 引用步骤号、工具名、观察证据，区分根因与后果、可恢复性、置信度；多类同现按"最早且能解释后续失败"选主因。Coding 六类错误：流程规范缺失、工具调用错误、作用域敏感文档格式、精确复制、模型执行异常、完成度与逻辑判断
- **两个精细归因案例**：引号问题不能全局替换——同一字符在中文散文、英文原文、行内代码、注释、JSON 里语法角色不同，要按片段类型定允许变换集，规则无法确定作用域时保留原文请求澄清是允许动作；old_string 失配不能只怪模型抄错——沿"原始字节→工具返回→序列化→模型输入→输出→解析→匹配"逐层找首个分歧，模型输出正确而传输层改变则根因归 Harness 或工具
- **两层回归任务**：端到端回归验证完整工作流——OSWorld、AndroidWorld、τ 都是；轨迹前缀回归冻结错误前的状态只测下一步决策——成本更低、隔离单点问题，答案定义为可接受动作集合加禁止动作清单。生产级 Agent 的前缀回归集往往比端到端更重要
- **实验 7-4 的三条硬结论**：混合方案没有自然胜出——3 题两单一方案都做不到、8 题不如最佳单一方案、平均奖励反低 0.092；纯 RAG 跨会话关联成功率仅 15%——检索到片段不等于拼对人物时间关系；180 次评判中幻觉否决真实触发 28 次——veto 不是装饰
- **实验 7-5 的结论**：三种等语义表示总分相同但失败位置不同；改变上下文表示不会自动修复应用策略——获得一条信息和正确将它用于当前决策是两种能力
- **同源模型与古德哈特定律**：度量一旦变成优化目标就不再是好度量——Agent 学会利用 judge 的偏好和盲点、避开它不擅长检测的错误。缓解：多源异构评判——Agent 用 Claude 则评判用 GPT 加 Gemini，不同家族偏见正交，难以同时欺骗所有评判者
- **多模态 judge 四方向**：TTS——准确性自然度音色情感，捕捉 WER 之外的韵律问题；ASR 语义影响——"转账一千"变"一万"才是关键；UI——提议者-审核者作评估方法；视频关键帧验证。方法论教训：选什么参考音频本身就是评估设计——固定参考来自 Fish S1 当然有利于 Fish Audio，比通用 TTS 不该把像不像 Fish 算进总分
- **配对比较与排名**：Elo 是 Bradley-Terry 模型的在线更新实现——爆冷带来更大分差调整；Chatbot Arena 匿名盲选数百万投票，局限是排名取决于用户问什么；位置偏差——judge 系统性偏向先出现的候选，标准缓解是交换顺序各评一次，两次不一致记平局或送人工
- **选型的吞吐延迟模型**：Prefill 定 TTFT——首字延迟等于排队加 Prefill，上下文越长越慢；Decode 定 tokens/s 和思考时长——50 tokens/s 生成 2000 思考 token 光思考就 40 秒；思考长度与效果不一定正相关，要自己实测；p95 尾部延迟比均值更反映真实体验；成本算成本-性能比——便宜但成功率低的模型重试后可能更贵
- **预算-能力曲线**：RE-Bench 人机对照——2 小时预算最佳 Agent 约人类专家 4 倍，8 小时被人类反超，32 小时人类约 2 倍——短预算领先不能外推长任务能力，选型要在接近真实时长的多个预算点上比较。多模型协同要评估验证整体效益——把"9.9 跟 9.11 哪个大"误判为简单题交给轻量模型就是反例
- **模型的行为策略是选型维度**：行动阈值——先广泛探索再改 vs 凭局部证据早改用测试反馈补齐；来源是 Harness 提示词加后训练。实验 7-8：GPT-5.6-sol 首次修改前平均 6.89 次工具调用读 4.67 个文件，Sonnet 5 是 4.56 和 3.56；两者测试全过——结论是行为策略随模型而变，不是谁更好
- **成本三层与不可加性**：模型推理——上下文累积放大（三轮 1000+2000+3000=6000 而非 3000）加思考 token；工具调用——外部 API 费加返回内容注入上下文后每轮反复计费；基础设施。八轮任务四组对照：稳定前缀省 28.3%、压缩历史省 17.5%、合计只省 30%——压缩同时缩短了可命中缓存的前缀；多项优化必须在完整任务一起实测，节省比例不能相加
- **统计显著性**：SE≈√(p(1-p)/n)——100 例 70% 时置信区间约 ±9 个百分点，73% 对 70% 不足以切换；比较两配置优先配对分析——McNemar 或配对 bootstrap，不是独立成功率相减；每配置 3-5 个种子报均值和波动；多重比较要收紧阈值。实务标准：分差超噪声、配对成立、能够复现，三者齐备才值得切换
- **可观测性**：trace 加 span 树借自分布式系统；OpenTelemetry 加 OpenInference 标准协议让采集与分析解耦；最有价值的去向是回流——生产失败轨迹脱敏后沉淀为评估集新用例和回归测试，评估集从静态集合变成贴近真实分布的活资产
- **从 Benchmark 到改进的纪律**：先检查评测系统再动 Agent——环境资源不足、评分器 bug、用例脱节，在数字上和模型退化一模一样；AndroidWorld 三轮案例：H1 加导航提示 25% 到 25%——提示补不回根本没看见的信息；H5 换 UIAutomator 元素树 25% 到 100% 但 token 涨到 2.498 倍；H5C 删无语义节点成功率保持 token 降到 0.506 倍——先解决能不能做成，再解决划不划算。一轮证据只支持与它规模相称的下一步，4/4 不能写成系统 100%
- **内部评估基础设施五组件**：消融基础设施——每个特性可独立关闭、定期验证贡献、发现特性债务，开关必须在启动路径极早期注入；AB 测试——多臂设计看剂量效应、区分机制指标与目标指标——缩短计划文件是机制，降低会话成本才是目标、护栏指标是不能变差的底线、记录基线统计；双层特性开关——编译时物理移除加运行时服务端下发，特性开关是一等公民架构组件；提示词敏感性——确定性渲染、版本快照、每次变更跑评估回归如 CI；隐私感知分析——类型系统编译时强制，隐私设计反而逼你想清真正要度量什么
- **仿真环境是评估到后训练的桥梁**：判分脚本直接就是 RLVR 的奖励脚本；训练提出评估不必操心的新要求——可靠的 reset 语义（残留状态污染梯度）和远高吞吐（数百万次对数千次）；AWorld 26 个 MCP 服务器 126 个工具、14.6 倍并行加速；RoboTwin2 双臂加动作分块；领域随机化缩 sim-to-real——适度提升泛化、过度让任务变得过难
- 全书定位：本章建第 1 章发现循环的证据段；方法论主线：观察、假设、实验、验证，使 Agent 工程从经验炼金术转向数据驱动科学

## 2. 实验

**7.1 运行 τ²-bench 并对比 τ-bench**
论证 人机交互型评估环境设计——任务定义三层：已知信息、任务指令、成功条件；τ² 的改进：事实锚定要求、精确成功条件（excellent 才算解决）、更真实的模拟用户、telecom 双控环境

**7.2 人肉执行基准测试任务**
论证 亲身体验六大数据集——简单中等困难各做一题，理解明确性与开放性的平衡、验证标准的客观可执行、难度层次化的必要

**7.3 构建基于 Rubric 的用户记忆评估**
论证 单一 judge 升级为结构化 Rubric——五维度四档制、每档具体判定标准、幻觉一票否决、边界案例进 edge_cases

**7.4 Advanced JSON Cards 与 RAG 对比**
论证 同一评估集公平对比——混合未自然胜出、RAG 跨会话关联 15%、180 次评判幻觉否决触发 28 次；说清每种方案的失效边界

**7.5 轨迹前缀边界评估**
论证 冻结上下文只测下一步决策——JSON Cards、Markdown、Python-like 三种等语义表示总分相同 6/11 但失败位置不同；改变表示不自动修复应用策略

**7.6 全自动 TTS 质量评估流水线**
论证 多模态 judge——四维度 Rubric 加多语料库；方法论教训：参考音频的选择本身就是评估设计，不是准备工作

**7.7 从配对比较数据构建排行榜**
论证 Elo 在线更新自零实现——对照官方 Bradley-Terry 极大似然：总体排名吻合、具体分值不齐；历史切片动画识别技术突破时刻

**7.8 固定 Harness 测量行动阈值**
论证 因果分离——同 Harness 换模型行为随模型变：GPT-5.6-sol 6.89 次工具 4.67 文件对 Sonnet 5 的 4.56 和 3.56，跨模块任务收敛、测试全过；工具步数、并行调用、延迟要分开看

**7.9 端到端成本分析**
论证 八轮任务四组开关对照——稳定前缀 28.3% 加压缩 17.5% 合计只 30%；优化合用必须在完整任务一起实测

**7.10 多维度模型性能基准测试**
论证 主流模型乘 API 提供商的选型数据库——TTFT、p95/p99、思考长度、限流点、MTTR、周级可用性探测

**7.11 用户记忆系统端到端选型**
论证 三个选择点联合评估——嵌入、reranker、主模型；发现强嵌入可能让 reranker 多余、强主模型可能弥补检索不足

**7.12 AndroidWorld 的评估和改进（三星）**
论证 从报告到改进的五步闭环——诊断、三层假设框架、单变量分阶段实验、成本收益决策、迭代；复现 H1 无效、H5 有效但贵、H5C 省一半 token 的完整链路

**7.13 配置 OpenVLA 与 RoboTwin2 具身环境**
论证 具身仿真——VLA 架构三视角 RGB 加 14 维关节状态、动作分块的影响、move_can_pot 的环境随机化与空间约束

## 3. 思考题

**1. LLM-as-a-Judge 使用语言模型评估语言模型的输出。这种"自我评估"是否存在系统性盲区——比如模型可能一致地给某种风格的回答打高分，而这种偏好与人类评判不一致？如何检测和校正这种偏差？**

Answer:
盲区存在且是系统性的：长度偏差、自信语气、结构化排版、同源偏好、位置偏差——方向稳定不是随机噪声，会一致地把某类风格推高。
检测：
- 金标集校准：人工标注 100-200 例测 kappa，低于 0.7 不放量——书里的原方案。
- 对抗式评审：构造表面完美藏错、关键词堆砌、迎合已知偏见的回答，看 judge 是否上当。
- 偏差审计：回归分数与长度、位置、格式的关系——高分总伴随长回答即已带偏。
校正：
- Rubric 显式惩罚冗长、规定长度上限。
- 多源异构评判：不同家族偏见正交，难以同时骗过所有评判者。
- 定期回炉：judge 或 Rubric 一更新就在金标集重新校准。

**2. 评估数据集的"防泄漏"设计至关重要。但在开源生态中，benchmark 数据一旦公开，很快就会被纳入训练数据。这场"猫鼠游戏"有终局吗？设计一种从根本上抵抗数据泄漏的评估方法。**

Answer:
没有绝对终局——公开数据终会进语料，这是现实；但可以把评估从"测记忆"拉回"测能力"。
- 动态生成：参数化模板加程序化生成——泄漏的只是模板，实例和答案在生成时才确定；验证基于最终状态而非操作序列，背答案无法通过。
- 时间新鲜度：持续收录训练截止后的新任务（SWE-bench-Live 路线）——评估永远领先语料一个版本。
- 过程性任务：多步组合加专创附件（GAIA 的互联网不存在文件）——单靠记住原文答不出。
- 泄漏可检测：金丝雀 GUID 埋入任务——模型能输出 GUID 即证明污染，可量化而非猜测。
- 私有 holdout 加定期轮换是商业实验室的兜底，代价是牺牲社区可审计性。
- 组合结论：动态生成加状态验证加新鲜度轮换三层叠加，把泄漏的收益降到趋近背题成本——不是消灭游戏，是让作弊不再划算。

**3. Scale AI 的四准则旨在消除评估的主观性。但某些任务维度（如"回答是否有帮助""语气是否恰当"）天然具有主观性。如何为这些主观维度设计可靠的 Rubric？**

Answer:
把主观判断转化为可观察行为。
- 行为化锚点："语气恰当"写成具体行为——对愤怒用户先致歉再解释、不用命令式、提供后续入口，每档配真实例句。
- 判例生长：主观维度先多人独立标注，分歧处就是边界案例，写进 edge_cases——Rubric 从抽象准则长成判例集。
- 权重降级：主观维度标可选项，不进必要项；一票否决只留给客观底线——幻觉与安全。
- 行为代理指标：有帮助性用后续行为代理——用户是否追问、是否采纳建议、是否复购。
- 接受残余主观性：改用配对比较——A 与 B 谁更好比 1-4 分打分更稳定，也绕开了绝对标准的模糊。

**4. τ-bench 通过模拟真实用户行为来评估 Agent。但模拟用户本身也是一个 LLM——它可能系统性地低估某些边缘场景（如情绪激动、表达不清的用户）。如何验证模拟用户本身的质量？**

Answer:
把模拟器当被评对象，给它建评估集。
- 金标对话集：真实客服记录改写成任务剧本，让模拟用户跑同任务，对比透露顺序、情绪表达、耐心终止是否复现真实分布。
- 边缘场景压力集：专门收集情绪激动、表达不清、中途改主意的真实案例——模拟器系统性低估的正是这些；测行为覆盖率。
- 图灵式检验：人类评委混排看真实对话与模拟对话，区分不出即合格。
- 敏感性分析：换不同家族模型演用户，评估结论是否漂移——漂移大说明结论依赖模拟器而非 Agent 能力，该改模拟器。
- 迭代清单：τ 到 τ² 的改进就是现成的质量维度——事实锚定、渐进透露、自然情绪波动。

**5. 配对比较（Bradley-Terry 模型）假设偏好是传递的（如果 A > B 且 B > C，则 A > C）。但人类偏好经常违反传递性。在 Agent 评估中，非传递偏好可能出现在哪些场景？这如何影响排名的可靠性？**

Answer:
非传递场景：
- 多目标 trade-off 循环：详尽对简洁、简洁对冗长、但带创意的冗长又胜详尽——准确、有用、简洁三轴上排序翻转。
- 任务分布依赖：编程题爱 A、闲聊爱 B、混合任务各半——聚合出循环；Chatbot Arena 的已知局限正是排名取决于用户问了什么。
- 场景依赖：同一个 Agent 长任务好短任务差，与相反者配对时胜负随题目时长翻转。
影响：BT 强行把偏好投影到一维实力分——丢失"偏好取决于任务分布"这一事实；换一批用户排名可能洗牌，点值排名给出虚假的确定性。
对策：分任务域分别排名；报告置信区间；用两两胜率矩阵暴露循环而非只用单一 Elo；写明排名所依据的分布。

**6. 本章区分了 Pass@k 的能力上限与 Pass consecutive@k 的业务可靠性。对于一个单次成功率只有 60% 的 Agent，怎样结合任务的失败成本、重试成本和副作用，决定应该报告哪个指标、取多大的 k？**

Answer:
按失败的可逆性分流，一个系统报两组数。
- 可逆加重试便宜（草稿、内部检索、生成候选）：报 Pass@k，k 取经济上合理的重试次数——p=0.6 时 k=5 约 99% 至少一次成功，用探索上限做决策；期望重试成本一起算。
- 不可逆加副作用（支付、退款、删数据、对外发送）：报 Pass^k，k 取生产中一个会话的真实调用链长度——p=0.6 连续 5 次只有 7.8%，这种环节根本不该自动放行。
- 决策式：自动化门槛 = 单次成功率的链长次方 ≥ 业务可接受阈值；不达标就降级辅助模式——Agent 提案、人批准，把链长砍到 1。
- 副作用任务禁止重试到成功——沙盒采样，每次失败计入可靠性指标。
- k 不是越大越好：Pass@k 随 k 单调升好看但失真，k 应绑定真实业务语义——一次交付内的尝试预算。

**7. 本章提出"观察→假设→实验→验证"的科学方法。但在实践中，Agent 的行为空间巨大，验证一个假设可能需要数百次评估运行。如何在有限计算预算下最大化评估的信息量？**

Answer:
把评估当实验设计问题——每次运行买最大信息量，不是最多分数。
- 配对设计优先：同任务同种子比 A/B，差分方差远小于独立采样——同预算统计功效最高。
- 分层分配：按能力标签分层，预算优先给历史分歧大的层——均匀撒网信息量低。
- 序贯实验：小样本先看方向，效应量大早停、小再扩——预算跟着不确定性走。
- 轨迹前缀代替端到端：验证单点假设用前缀回归，一次运行只测一个决策边界，便宜一个量级。
- 缓存复用：轨迹缓存，只重跑受改动影响的层。
- 假设按可证伪成本排序：便宜的先试——AndroidWorld 案例的 H1 到 H5 顺序哲学。

**8. AndroidWorld 小实验中，完整元素树把成功率从 25% 提高到 100%，却把 token 用量推到 2.498 倍；精简后成功率不变，token 降到对照组的 0.506 倍。怎样设计一套自动裁剪规则，既删掉无语义的 UI 节点，又不误删对可访问性、状态验证或后续操作有用的信息？**

Answer:
按四类信号分层保留，删的只是无语义容器。
- 可删：纯布局容器（无文本无 handler 无语义角色）、不可见节点、零面积节点。
- 必保：可交互（有 handler）、有语义角色（aria/contentDescription）、状态载体（checked/selected/disabled）、验证锚点——任务成功条件引用的字段，从任务描述反查。
- 保序保坐标：删节点不改变兄弟相对顺序，保留父级坐标信息——后续点击定位依赖。
- 裁剪规则自己要有回归测试：规则改动跑前缀回归集——H5C 的方法论递归适用，防下次误删。
- 拿不准就保：删错（看不见关键信息）的代价大于多花 token——保守默认。

**9. τ-bench 的用户模拟采用了"渐进式信息透露"——不一次性提供所有信息，而是根据 Agent 的提问逐步透露。这种设计如何影响评估结果？如果模拟用户的信息透露策略与真实用户差异较大，评估结论还可靠吗？**

Answer:
影响：
- 它测出被传统基准漏掉的能力——主动提问澄清；一次性全给时 Agent 只需执行，渐进透露还要会问，得分通常更低但更接近真实。
- 改变失败形态：沟通低效触发耐心耗尽终止——同时测了效率和正确性。

可靠性边界：
- 对 Agent 的澄清与沟通策略排序：基本可靠——不太依赖透露节奏。
- 对领域知识正确性：基本可靠。
- 对绝对成功率数字：要打折扣——透露激进压低分数、节奏快抬高，数字依赖模拟器超参。
- 缓解：金标对话校准模拟器；报告透露策略参数；结论用相对排序表述——两者对同一模拟器敏感度相近时排序稳定。
- 红线：换一个透露策略就翻转的结论不要发布——那是模拟器的结论，不是 Agent 的。
